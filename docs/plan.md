# 다음 단계 계획 (2026-11-19)

마을 생활 게임의 본보기(동물의 숲: 새로운 수평선)를 다시 조사해서, 지금 게임에 빠져 있는 뼈대를 정리하고 만드는 순서를 정했다.
이 문서는 작업 기록을 겸한다. 끝난 항목은 `[x]` 로 바꾼다.

## 1. 조사한 것 (구조만 참고하고, 이름·캐릭터·그림·대사는 가져오지 않는다)

| 본보기의 구조 | 우리 게임에 지금 있는 것 | 고칠 방향 |
| --- | --- | --- |
| 텐트 한 채와 이웃 두 명으로 시작한다. 가게·박물관·다리·집터는 재료와 채집물을 모아 하나씩 세운다 | 처음부터 집·가게·박물관이 다 있고 이웃 여섯이 산다 | **천막에서 시작**, 이웃 2명. 나머지는 할 일을 해내면 생긴다 |
| 생물 5종을 보여 주면 박물관장이 천막을 치고, 15종을 더 기증하면 건물이 선다 | 박물관이 처음부터 있다 | 같은 두 단계로 |
| 박물관은 곤충·물고기·화석 전시관이 따로 있고, 기증한 것이 살아서 전시된다 | 방 하나에 기증 창구만 있다 | 로비 + 곤충관 + 민물 수족관 + 바다 수족관 + 화석관 |
| 물고기 80종(강·연못·강어귀·바다·부두·상류), 곤충 80종. 종마다 생김새가 다르다 | 물고기 38, 곤충 33. 몇 가지 틀에 색만 바꿔 찍어 냄 | 80종씩, **종마다 윤곽·지느러미·무늬·색을 따로** |
| 날마다 바뀌는 작은 일감 다섯 개와, 오래 걸리는 도전 과제 | 없다 | 수첩(할 일 / 오늘의 일감 / 도전 과제) |
| 시작할 때 피부·머리 모양·머리색·눈·코입·볼을 고르고, 나중에 거울에서 바꾼다 | 정해진 네 가지 모습 | 부위별로 고르는 꾸미기 + 집 안 거울 |
| 도구마다 몸짓이 다르다 | 잠자리채와 삽·도끼가 비슷하게 내려친다 | 잠자리채는 머리 위에서 내려찍기, 삽은 두 손으로 땅에 꽂아 퍼 올리기, 도끼는 옆으로 휘두르기 |
| 친구 섬에 놀러 간다 | 혼자만 | 방 코드로 친구 마을에 놀러 가기(스페이스 크래프트와 같은 방식) |

## 2. 만드는 순서

### A. 도구 몸짓 (`js/gfx/actor.js`)
- [x] 자세 값에 '자루의 어디를 쥐는지(g)', '도구를 옆으로 돌린 각(y)', '자루를 축으로 돌린 각(r)', '몸을 비튼 각(w)' 추가
- [x] 잠자리채: 등 뒤로 젖혔다가 머리 위로 크게 내려찍기
- [x] 삽: 평소엔 날을 아래로 짚고 다님 → 두 손으로 들어 땅에 꽂기 → 젖혀서 흙 퍼 올리기
- [x] 도끼: 몸을 틀어 옆으로 휘두르기
- [x] 물뿌리개: 기울이면 물줄기

### B. 물고기·곤충 (`tools/blender/fishkit.py`, `topkit.py`, `bugkit.py`, `paint.py`, `data/*.json`)
- [x] 물고기: 종마다 옆모습 그림(몸 윤곽, 등·옆구리·배 색, 줄무늬·점·얼룩, 지느러미, 눈)을 그려 몸에 입힌다
- [x] 곤충: 종마다 위에서 본 그림(날개 무늬, 딱지날개 점, 몸 마디 색)을 그려 입힌다. 무리별 몸 틀(나비, 딱정벌레, 메뚜기, 잠자리, 매미, 벌, 노린재 …)
- [x] 게·가재·거북·개구리·가오리·아귀·해파리처럼 위에서 본 모습이 특징인 물속 생물도 같은 방식(`topkit.py`)
- [x] 물고기 80종(민물 40 · 바다 40), 곤충 80종. 사는 곳에 '강 상류' 추가, 곤충이 있는 곳에 '물가·길 위·모래밭' 추가
- [x] 도감을 민물고기 / 바닷물고기 / 곤충 / 화석으로 나눔
- [x] 묶음 파일을 `fish.glb` · `bugs.glb` 둘로 나누고 그림은 webp로 줄여 넣음(합쳐 약 8.2MB: 몸을 촘촘히 나눈 뒤 곤충 쪽이 5MB로 늘었다)
- [x] 전 종을 실제 생김새와 견주어 다시 손봄(2026-11-20). 고친 내용은 `docs/blender.md` 의 '종별 점검 기록'
- 종마다 맞는지는 `catalog.html?b=fish`, `catalog.html?b=bugs` 로 전부 펼쳐 놓고 본다(그림만 보고 넘어가면 모델에 입혔을 때의 잘못을 놓친다).
- 남은 손질: 연어 수컷의 굽은 턱, 나비의 날개 아랫면(접었을 때 무늬)은 없다. 곤충 묶음이 5MB라 느린 회선에서는 첫 화면이 오래 걸릴 수 있다(꼭짓점 압축을 쓰면 줄일 수 있다).

### C. 박물관 전시관 (`js/game/museum.js`, `rooms.js`, `scripts.js`)
- [x] 방에서 방으로 가는 문: 방 정의의 `portals`(뒷벽의 문), `exitTo`(아래 문으로 나가면 가는 방). 문으로 걸어 들어가면 넘어간다
- [x] 로비 + 화석관 + 곤충관(통나무·꽃밭·연못·가로등이 있는 정원) + 민물 수족관(강 상류 / 강과 강어귀 / 연못 / 얕은 물가) + 바다 수족관(큰 수조 / 모래 바닥)
- [x] 기증한 생물이 전시관에서 움직이고, 앞에서 Space를 누르면 이름과 설명이 뜬다. 전시관마다 현황판
- 남은 손질: 수조의 물고기가 좌우로만 오간다(앞뒤 움직임 없음). 화석관은 전시대 12개가 꽉 차면 끝이다.

### D. 처음부터 키워 가는 마을 (`js/game/quests.js`, `scripts.js`, `daily.js`, `state.js`, `main.js`)
- [x] 시작: 내 천막(4×4칸), 이웃 2명, 마을회관, 까미의 천막 좌판. 박물관 자리·집터 6곳·둘째 다리는 비어 있음
- [x] 재료: 나무(다 자란 나무를 도끼로 찍을 때마다 1개, 쓰러질 때 2개), 돌(삽으로 바위를 두드리면 바위마다 하루 3개). 나뭇가지는 넣지 않았다
- [x] 할 일 9단계: 이장님 찾아가기 → 이웃과 인사 → 생물 5종 → 내 집 → 가게 짓기 → 박물관(15점 기증) → 새 이웃 세 집 → 다리 → 마을 잔치. 공사는 모두 다음 날 끝나고 편지가 온다
- [x] 오늘의 일감 다섯 개(해내면 새 일감, 손대지 않은 것은 날마다 바뀜), 도전 과제 14가지
- [x] 수첩(N): 할 일 / 오늘의 일감 / 도전 과제. 화면 왼쪽 위에 지금 할 일 한 줄
- [x] 예전 저장은 '다 지어진 마을'로 이어받는다
- 숫자와 규칙은 `docs/design.md` 의 '마을 키우기'에 적었다.
- 남은 손질: 이야기가 한 줄기뿐이다(순서를 바꿀 수 없음). 다리·집터의 자리를 고를 수 없다. 잔치 뒤의 긴 목표는 도전 과제뿐이다.

### E. 캐릭터 꾸미기 (`tools/blender/chars.py` 의 `custom()`, `js/game/look.js`, `js/game/lookui.js`)
- [x] 부위를 갈아 끼우는 주인공 모델(`player_custom`): 머리 모양 9, 눈 7, 입 5, 볼, 옷 6, 모자·머리 장식 7, 안경 3
- [x] 피부색 7 · 머리색 11 · 눈 색 6 · 옷과 모자 색 13 · 신발 색 6
- [x] 시작 화면('이사 준비')과 집 안 거울에서 고르기. 돌려 볼 수 있는 미리보기, 본보기 네 가지, '아무렇게나'
- [x] 예전 저장은 정해진 모습 그대로 이어지고, 거울에서 바꾸면 꾸미는 모델로 넘어온다. 거울은 편지로 보내 준다
- 전부 늘어놓고 확인하는 화면: `catalog.html?b=looks`
- 남은 손질: 옷과 모자를 처음부터 다 고를 수 있다(가게에서 사 모으는 재미는 아직 없다). 머리카락은 둥근 덩어리 모양이라 가닥 표현은 없다.

### F. 같이 하기 (`js/game/net.js`)
- [x] 방장이 문을 열면 4자리 방 코드가 나오고, 친구가 그 코드로 방장의 마을에 놀러 온다(공개 MQTT 중계 서버 세 곳, 자체 서버 없음). 8명까지
- [x] 서로의 모습(꾸민 그대로)·걷기·도구 몸짓·말풍선(T)·잡은 것 자랑이 보인다. 방장 마을의 이웃 주민도 같은 자리에 보인다
- [x] 땅 위의 것(떨어진 과일, 놓은 물건 등)이 모두에게 똑같이 바뀐다
- [x] 손님은 낚시·채집·줍기·놓기를 할 수 있고, 삽·도끼·건물 출입은 막았다. 손님의 자기 마을 저장은 건드리지 않는다
- 확인한 방법: 내 컴퓨터에 띄운 중계 서버로 창 세 개(방장 1, 손님 2)를 붙여서 시험했다. **실제 공개 서버로 이어지는지는 여기서 확인하지 못했다**(작업 환경에서 바깥 서버로 나갈 수 없음). 주소는 별지기(starwatch)에서 쓰는 것과 같다
- 아직 없는 것: 중계 서버가 막힌 곳을 위한 예비 통로(PeerJS 직접 연결), 손님의 건물 출입, 방장 교대
